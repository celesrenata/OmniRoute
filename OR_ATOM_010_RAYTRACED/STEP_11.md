# STEP 11: opt-in GPU / atom detail view

Base commit: `0c3d063b9` (plus the Step 11 commit that carries this file). Branch `feat/atomic-raytraced-renderer`. Not deployed, nothing pushed.
Environment: macOS, Apple M5 Max, headed Chrome via Playwright (real GPU), dev server from this worktree on :20199, golden DEMO topology (`/dev/atomic-bench?atoms=20`).

## What it is

The viewer focuses an atom (label click), the tooltip offers "Open detail view", and the camera flies in (low, near eye-level idea5-style hero framing, revision 2) while a DOM panel shows that atom's real telemetry. Escape / "Back to topology" restores the previous framing. The default view never changes: no detail code runs unless the viewer opts in.

## Honesty rules (directives 7 and 30)

- Values come from the descriptor; null device measurements read "no data", never 0.
- Active/Queued job panels appear only when `activeJobs`/`queuedJobs` are non-null (a real 0 is shown). Failed appears only from real `request-failed` events in the lifecycle pool for that provider within 60 s. GPU atoms have no provider id, so failures are never attributed to them. No value, no panel.
- Model to nucleon mapping uses only observed model ids and the scene's own deterministic nucleus allocator, with a basis label (live in-flight, call-log window, fleet residency). No model observed gives "neutral two-tone", nothing guessed.
- Activity wording reuses the tier text ("idle, no measured activity", "recent activity Nm ago"), so decorative vitality is never presented as live work.

## Static electrons (directive 36)

Reproduced live first: sampled `window.__atomicElectronDbg` (dev hook in `atomBatch.ts`) twice, 1 s apart. Root cause by code reading plus the numbers: electron angles used `wire.speed (0.35..0.85) x 1.4 x phase`, and `phase` advances at the energy `speedMul` (floor 0.15). The slowest orbit of a low-energy atom therefore turned at 0.15 x 0.35 x 1.4 = 0.074 rad/s (about 85 s per lap), which reads as "static", and one or two of an atom's 11 wires are always in that slow band. Not the cause: no null/zero measured signal feeds electrons (spin is separate), no duplicate legacy/LOD electron layer exists (one wire batch), the time uniform is wired for every row, and the `paused=1` state is a deliberate hold.
Fix (`scene/electronMotion.ts`, `rt/atomBatch.ts`): a dedicated decorative electron clock per atom, rate 1.0 + 1.6 x speedMul (energy tier only, never measured tok/s), advanced with dt (0 when paused) and held exactly under reduced motion. Minimum angular speed is now 1.0 x 0.35 = 0.35 rad/s at the lowest tier. The wire pulse bands use the same clock. Nucleus spin is untouched.
Live (real M5 Max, `scripts/ad-hoc/pw-atomic-electrons.mjs`, `electrons-report.json`), displacement per orbit over 1 s: bench paused=0, 22 atoms / 242 orbits: min 0.43 rad, median 0.95 rad, 0 still orbits; real `/home` Atomic, 10 atoms / 110 orbits: min 0.52 rad, median 1.16 rad, 0 still orbits; paused=1 and reduced motion: all 242 orbits hold exactly (0 rad). Unit test `electronMotion.test.ts` asserts every wire (all 11 per seed, both electrons) advances > 0.3 rad/s at every tier, and pause/reduced hold.

## Checkpoint 3c (directive 38 + 37; supersedes "Console errors" and "Nucleus clipping artifact" above)

Commits (one per item): 38.3 toggle `de4924725`, 38.4 notch `7d526254d`, 38.1 framing `234a65d1d`, 38.5 unmount `909b80c1e`, 37 traces `9e3d55e58`, trace re-route perf fix `123235d81`.

- 38.1 Detail framing (`scene/detailFlight.ts`, `scene/AtomicScene.tsx`). The safe area is the canvas rect minus the measured DOM overlays: legend, detail panel, controls, status, and the host 2D/Atomic toggle (skipped when the host is fullscreen). The span from the envelope top to the front and back of the pad is fitted to 88% of the safe area. A lens shift (`camera.setViewOffset`) centres the atom in the safe area, and the FOV (18–55°) keeps the horizon in frame. Labels follow the shift via `--atomic-lens-x/y`. Resize, overlay mutation and `fullscreenchange` recompose. The yaw sweep avoids neighbours that would block or crowd the atom. Esc and Reset clear the view offset and the CSS vars. Verified live on real `/home`: OpenAI and hub, in the card and in fullscreen. Every run ends with `viewOffsetCleared: true`, the panel gone and the camera back at the default pose. The 1–2 unit difference is the existing idle sway. The safe area and composition chosen are recorded per run in `signoff2-report.json`.
- 38.2 = directive 37 Copper traces (`scene/traceRouter.ts`, `scene/shaders/boardTraces.ts`). Real instanced geometry, not painted lanes. A deterministic octilinear router produces 885 nets / 5200 segments / 257k units: long buses with 45° legs, branches that inherit arc length so pulses run on into them, pads, joints, and additive flares with sparks. Shading is metallic copper (F0 0.95/0.52/0.28) with an environment reflection. Pulses freeze under reduced motion. The painted lane stubs on the floor are gone (walls and ceiling unchanged). Routing costs about 300 ms, so it is cached by board extent and pads. Without the cache, every telemetry or aspect update re-routed and caused ~200 ms frame spikes (`123235d81`).
- 38.3 Toggle: Atomic mode only, fixed dark glass matching the controls; 2D mode unchanged. Contrast from the computed colours: "2D" (inactive) 12.4:1 on black, 11.2:1 over the dark scene, 7.3:1 over mid-grey. "Atomic" (active) is 10.4–10.8:1. The theoretical worst case for the inactive label is 2.7:1, over a pure-white backdrop behind the 20% translucency; the backdrop under the toggle is the dark wall.
- 38.4 Notch root cause: nucleons are traced only through the nucleus glass sphere (1.14 × pack extent). At IOR 1.32 the refraction magnified side and rear nucleons until their image reached the glass silhouette and was cut off there. Fix: IOR 1.08, glass size unchanged (`scene/glassOptics.ts`, `glassOptics.test.ts`).
- 38.5 Console errors. The React "synchronously unmount a root" warning was ours: under StrictMode, the 2D renderer's double-mount guard called `root.unmount()` inside the commit.
