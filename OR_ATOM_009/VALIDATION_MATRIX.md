Use real/browser captures. For simulated data, mark **DEMO** conspicuously. For disconnected metrics, mark **UNAVAILABLE**.

> **All rows below are DEMO evidence.** Every scenario body is built by the app's own
> `buildDemoSnapshot()` + `reconcileSnapshot()` (byte-for-byte the real endpoint's shape) and is
> served to the **real** `FleetTelemetryPoller` via a network-layer intercept (`page.route`) — the
> app code is unmodified. Values below are read from the served demo body + the live page
> (`captureScenarios.json`, `toggleStability.json`, `soak-mixed-lanes.json`,
> `contextLoss-mixed-lanes.json` in `OR_ATOM_009/screenshots/`).
>
> **Source column**: `demo:` = value from the deterministic demo body (never a live production
> measurement). **Age** = the demo body's age as the poller's clock saw it at capture
> (fresh scenarios are pinned at `t` at build → age ≈ settle time; `unknown-stale` is pinned at
> `t−15 s`). **Nucleus speed / cloud hue / discharge result** are the _expected rendered
> behavior_ for the served signals per the Phase-3 binding contract (speed ∝ measured TPS,
> lane hue by lane type, one-shot pulses from lifecycle events); the PNGs are the observed
> canvas state at that moment. The scene's _dynamic_ pulse/rotation cannot be asserted from a
> single still frame — those are covered by the Stability soak (per-minute pixel diffs prove
> continuous animation) and by `expectedSignals` in `demoHarness.ts`.

**Known gaps (honest):**

- The matrix row specifies a **20-min** soak; the **10-min** soak was run (the 20-min variant is
  one env var: `DURATION=1200`). 20 min = NOT RUN.
- `renderer.info` (draw calls / geometry / texture counts) is **UNAVAILABLE** in this checkout —
  no module exposes the `window.__atomic.rendererInfo` handle; the harness reports it rather than
  fabricate numbers.
- `completion` / `failed-request` **discharge pulses** are lifecycle-event driven and the demo
  body deliberately does not synthesize lifecycle events (a snapshot cannot carry them) — those
  one-shot pulses are NOT RUN in demo mode; the honest post-event _quiet-state_ telemetry IS
  captured (rows above).

Always label unperformed tests as **NOT RUN**; build success is not browser validation.
